# STM32 多功能电子钟（OLED + RTC + 温湿度 + 闹钟）

基于 **STM32F103C8T6** 的多功能电子钟：RTC 走时、DHT11 温湿度采集、OLED 显示、按键 + 旋转编码器设置时间与闹钟、闹钟到点蜂鸣器响铃，所有显示与时间逻辑均做了模块化封装。

- 平台：STM32F103C8T6（Cortex-M3，72MHz，64KB Flash / 20KB SRAM）
- 开发环境：Keil MDK V5.06（ARMCC V5.06，C99）+ STM32F10x 标准外设库 V3.5.0
- 工程文件：`project.uvprojx`

---

## 一、功能特性

- [x] **RTC 走时**：外部 32.768kHz 晶振（LSE），带 VBAT 时可掉电走时
- [x] **显示**：日期 + 星期 + 时间 + 温度 + 湿度 + 闹钟状态（OLED 128×64，8×16 字体）
- [x] **时间设置**：按键 + 旋转编码器修改年/月/日/时/分/秒，带闰年与月末处理、字段回绕
- [x] **闹钟设置**：时/分/开关，支持主界面一键开关
- [x] **闹钟功能**：到点蜂鸣器（PA7）响铃，任意按键或旋转编码器立即停止，30 秒自动停止
- [x] **掉电保存**：闹钟配置保存在后备寄存器 BKP_DR2~DR4（有纽扣电池时不丢失）
- [x] **可靠性设计**：
  - DHT11 读取加入超时保护，传感器未接时显示 `--`，系统不卡死
  - RTC 计数器双读 CNTH，规避进位瞬间读到偏大 65536 秒（约 18 小时）的问题
  - LSE 最多等待 5 秒，不起振自动回退内部 LSI，避免上电黑屏死锁
  - 按键/编码器非阻塞边沿检测，编码器计数的读-清零过程关中断保护
- [x] **显示封装**：`OLEDShow` 统一管理所有界面，主函数不直接调用 OLED 驱动

### 主界面布局

```
2026-10-25 SUN      日期 + 星期
TIME 21:31:55       时间
T:26C H:60%         温度 / 湿度（读取失败显示 --）
ALM:07:30 ON        闹钟时间 + 开关状态
```

## 三、操作说明

| 操作 | 正常界面 | 编辑界面 |
|---|---|---|
| KEY1（PA1） | 进入**修改时间** | **保存**并返回 |
| KEY2（PA3） | 进入**修改闹钟** | **切换修改项** |
| 旋转编码器 | — | 调整当前数值（时间：年→月→日→时→分→秒；闹钟：时→分→开关） |
| 编码器按键（PA9） | 闹钟**开 / 关** | **放弃**修改并返回 |
| 闹钟响铃时 | 任意按键或转动编码器立即停止，30 秒后自动停止 | — |

编辑界面中，当前修改项用 `[ ]` 括起，第 4 行显示操作提示 `K1:SAVE K2:NEXT`。

### 关键设计

1. **显示与业务分离**：`main.c` 只调用 `OLEDShow_ShowTime()/ShowTempHum()/ShowAlarm()/EditTime()/ShowRing()`，所有行列坐标集中在 `OLEDShow.c`，更换屏幕或调整布局不影响业务逻辑。
2. **时间与闹钟独立模块**：`Time.c` 负责 RTC 读写、字段调整、闰年/月末/星期计算与闹钟持久化；`main.c` 只做状态机与输入调度。
3. **编辑用临时副本**：进入编辑状态时复制当前时间/闹钟，旋转编码器只改副本，KEY1 才写回 RTC/BKP，编码器按键可取消。
4. **闹钟触发去重**：用 `last_minute_key`（时<<8 | 分）检测“进入新的一分钟”并只触发一次，同一分钟停止响铃后不会重复触发。
5. **非阻塞输入**：按键/编码器按键采用“下降沿 + 20ms 复检”消抖，长按只触发一次；主循环不会被按键阻塞。
6. **显示防残影**：每行写完后用 `ClearToEnd()` 补空格；闹钟开关行固定 5 字符宽度，避免切换编辑项时残留 `]` 等字符。

## 五、踩坑记录

### 1. 设置完时间后快了/慢了 8 小时

- **现象**：用按键设置 21:00，保存后显示 05:00（次日）。
- **原因**：`MyRTC_ReadTime()` 对 RTC 计数器做了 `+28800`（东八区）修正，但 `MyRTC_SetTime()` 直接 `mktime()` 写入，没有减回 8 小时，读写约定不一致。
- **解决**：读写成对修正 `+8h / -8h`，并初始化 `tm_isdst = 0`（否则 `mktime` 读取未初始化的夏令时字段，结果不确定）。

### 2. 时间偶发跳变约 18 小时

- **现象**：RTC 计数偶尔比实际大 65536 秒。
- **原因**：库函数 `RTC_GetCounter()` 先读 `CNTL` 再读 `CNTH`，若在 `CNTL` 进位瞬间读取，会读到旧高字 + 新低字。
- **解决**：自己实现读两次 `CNTH` 比对：

```c
uint32_t MyRTC_GetCounter(void)
{
    uint32_t high1, high2, low;
    do
    {
        high1 = RTC->CNTH;
        low   = RTC->CNTL;
        high2 = RTC->CNTH;
    } while (high1 != high2);
    return (high1 << 16) | (low & 0xFFFF);
}
```

### 3. 没有晶振时上电黑屏、程序卡死

- **现象**：LSE 未起振的板子上电后 OLED 不亮、无任何反应。
- **原因**：`while (RCC_GetFlagStatus(RCC_FLAG_LSERDY) != SET);` 无限等待。
- **解决**：带超时等待（5 秒），超时后关闭 LSE、改用内部 LSI（40kHz，预分频 40000-1）继续运行；复位后按 `RCC->BDCR & RCC_BDCR_RTCSEL` 重新使能对应时钟源，避免 LSI 的 `LSION` 位被复位清零后 RTC 停走。

### 4. 旋转编码器数值乱跳或不计数

- **现象**：编码器转一格数值跳 2~3，或完全不响应，按键也没反应。
- **原因**：原代码把 A/B 相 `GPIO_Init` 到了 **GPIOB**，但 EXTI 线和中断映射的是 **PA4/PA5**，PA4/PA5 实际处于浮空输入，抖动大且电平不确定。
- **解决**：A/B/按键统一配置为 GPIOA 上拉输入；读数与清零过程用 `__disable_irq()/__enable_irq()` 保护，计数器加 `volatile`。

### 5. 编辑界面返回主界面后残留字符

- **现象**：主界面显示 `T:26C]H:60%`、`ALM:07:30 ONXT` 之类的残留。
- **原因**：编辑界面字符串比主界面长，切回主界面时只覆盖了部分列，行尾旧字符没被清除。
- **解决**：每行写完后统一 `ClearToEnd()` 用空格补到第 16 列；开关状态行改成固定 5 字符宽（`" ON  "` / `" OFF "` / `"[ON ]"` / `"[OFF]"`）。

### 6. 不接 DHT11 时整机死机

- **现象**：温湿度传感器没接或接触不良时，程序停在 `while(Read_Data == 0);`。
- **原因**：单总线位读取没有超时。
- **解决**：增加 `DH11_WaitLevel()` 超时（约 6000 次轮询），5 字节数据校验和错误或超时则返回失败，界面保持显示 `--`。

### 7. 闹钟保存过程中掉电导致配置异常

- **原因**：先写 magic 再写数据，若写数据时掉电，下次上电 magic 有效但数据是旧值。
- **解决**：改为先写时分/使能、最后写 magic；读取时校验 magic 后再对时/分做范围检查。

### 8. 按键按下后主循环被“卡住”

- **现象**：按住按键不放时，时间不刷新、编码器不响应。
- **原因**：原 `Key_GetNum()` 用 `while(按下)` 等待松手，属于阻塞式。
- **解决**：改为“记录上次电平 + 下降沿触发 + 20ms 复检”的非阻塞实现，长按只返回一次。

## 七、已知限制与后续计划

- **掉电保持依赖 VBAT**：无纽扣电池时断电后时间回到 `MyRTC.c` 中的初始值（2026-10-25 21:31:55），需要重新设置；闹钟同理。
- **年份限制 2000~2037**：`time_t` 为 32 位有符号，2038 年溢出，代码中已限制可设置范围。
- **LSI 回退精度低**：LSE 损坏时自动使用内部 LSI，走时误差会明显增大，仅作为“不黑屏”的兜底。
- **编码器无硬件消抖**：机械抖动较大时可能出现偶发多计数，后续可加 RC 滤波或改用 TIM 硬件编码器接口。
- **后续可扩展**：UART 命令协议（DMA + IDLE 中断 + 环形缓冲）、IAP Bootloader 串口升级、FreeRTOS 多任务重构、STOP 低功耗模式、Flash 参数存储、联网 NTP 对时。
